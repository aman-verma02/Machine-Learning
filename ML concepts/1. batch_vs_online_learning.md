
## Batch Learning

The model is trained on the **entire dataset at once**, then deployed. It doesn't learn incrementally from new data as it arrives.

**How it works:**
- Collect all training data
- Train the model in one go (or a few passes/epochs over the full dataset)
- Deploy the trained model
- To incorporate new data, you retrain from scratch (or from a checkpoint) on the full updated dataset

**Characteristics:**
- Also called "offline learning"
- Needs significant compute/time/resources per training run
- Once deployed, the model is static until the next retrain
- Works well when data doesn't change fast and you have the resources to periodically retrain

**Example:** Training a fraud detection model once a week on all transactions from the past month, then deploying that fixed model until next week's retrain.

## Online Learning

The model is trained **incrementally**, learning from data as it arrives — one instance or small mini-batch at a time.

**How it works:**
- Feed data sequentially (a stream)
- Model updates its parameters after each instance/mini-batch
- No need to store the whole dataset — you can discard data after learning from it
- The model keeps adapting continuously

**Characteristics:**
- Cheap, fast updates — good when data arrives continuously (streaming)
- Great for **concept drift** — when the underlying data patterns change over time (e.g., stock prices, user behavior)
- Risk: bad or noisy data can degrade the model quickly since it updates live — you often need to monitor performance and have a rollback plan
- Learning rate matters a lot — how much weight new data gets vs. old learned patterns

**Example:** A recommendation system that updates as users click, adapting to trending preferences in real time.

## Key Tradeoff Table

| | Batch | Online |
|---|---|---|
| Data availability | Need full dataset upfront | Can start with a stream |
| Compute pattern | Heavy, periodic | Light, continuous |
| Adaptability | Slow (only updates on retrain) | Fast (updates continuously) |
| Risk of drift | Model can go stale between retrains | Can adapt to drift automatically |
| Risk of corruption | Lower (controlled retrain env) | Higher (bad data can hurt immediately) |
| Typical use case | Stable environments, resource-rich | Streaming data, resource-constrained, fast-changing environments |

A useful mental model: batch learning is like studying for an exam by cramming with all your notes at once; online learning is like learning on the job, updating your understanding a little every day as new info comes in.

## When to Use Online Learning

Online learning makes sense when one or more of these apply:

**1. Data arrives as a continuous stream**
You don't have (or want) the full dataset upfront — e.g., sensor readings, clickstreams, transaction logs coming in nonstop.

**2. The data is too large to fit in memory**
Instead of loading everything for batch training, you process instances (or small chunks) one at a time and discard them after learning.

**3. The underlying patterns change over time**
If user behavior, market conditions, or system behavior shifts, a static batch-trained model goes stale. Online learning keeps adapting.

**4. You need fast/cheap updates**
Retraining a huge model from scratch every day/hour is expensive. Online learning updates incrementally — much lighter compute footprint.

**5. Limited resources / out-of-core learning**
Even if data doesn't drift, if you can't afford the compute for full retraining, online learning lets you train on data you can't hold all at once.

**Common real-world uses:** fraud detection, ad click-through prediction, recommendation systems, stock price prediction, spam filters, IoT sensor monitoring — anywhere "yesterday's patterns" might not hold today.

**When NOT to use it:** if your data is stable, fits in memory, and doesn't change much — batch learning is simpler, more stable, and easier to control/debug. Online learning also carries more risk since bad data can corrupt the model live.

## Concept Drift

Concept drift means **the statistical properties of the target variable (what you're trying to predict) change over time**, so a relationship the model learned in the past no longer holds.

In other words: the *concept* the model learned — the mapping from inputs to outputs — literally drifts away from reality.

**Types of concept drift:**

| Type | Description | Example |
|---|---|---|
| **Sudden drift** | An abrupt change at some point in time | A new competitor product suddenly shifts customer buying patterns |
| **Gradual drift** | Slow, steady change over time | Language/slang evolving in a sentiment analysis model |
| **Recurring drift** | Old patterns come back later | Seasonal shopping trends (holiday spikes) |
| **Incremental drift** | Small changes accumulate over time | Gradual wear on a machine sensor changing "normal" readings |

**Why it matters:** A model trained on old data can degrade in accuracy silently — it still makes predictions, they're just increasingly wrong. This is dangerous because nothing "breaks" loudly; performance just quietly decays.

**How it's detected/handled:**
- Monitor live model performance metrics (accuracy, error rate) over time and alert on drops
- Statistical tests comparing distributions of new data vs. training data (e.g., **Population Stability Index**, **KL divergence**, **ADWIN** algorithm)
- Periodic retraining or online learning to continuously adapt
- Sliding window approaches — only train on recent data, discard old data assumed to be outdated

A simple way to remember it: **online learning is the "how" (a training strategy), concept drift is the "why" you might need it** (a real-world problem online learning helps solve).
